## Чистый Docker и настоящий API

Отдельный клон содержал только отслеживаемые файлы. В нём отсутствовали локальные artifacts обучения, личные environment-файлы и node_modules. Использовались новые PostgreSQL/document тома и собственный Compose-проект. JSON выбранной модели вошёл в обычный образ; build, автоматические миграции, up и seed завершились успешно. При сборке использовался кеш слоёв Docker: скачивание всех пакетов заново и build без кеша не проверялись.

Через nginx, API, worker и PostgreSQL пройдены восемь случаев:

1. Все шесть продуктов: одобрение с ручным решением там, где оно требуется, подготовка, подтверждение клиента и завершение сотрудником.
2. Меньшее принятое предложение: запрос 5 млн ₽ заменён согласованными 1 млн ₽ / 24 месяца; Deal сохранил именно эти условия.
3. Отмена незавершённого оформления.

Повтор команды с тем же ключом вернул прежний результат без дублирования истории. Компания другого клиента не смогла скачать условия. После полной остановки и запуска Compose сохранились все восемь сделок, версии, сгенерированные условия и SHA загруженных PNG. Это технические синтетические файлы; достоверность финансового содержимого не оценивалась.

С отключённым LLM chat вернул ожидаемый 503, а карточка и завершённая сделка оставались доступны. Это проверка необязательности помощника, а не успешный ответ без провайдера.

## Проверка интерфейса

89 targeted frontend tests проверяли рассмотрение, риск, расширенный каталог, удобство кабинета, отзыв и оформление. **19 Deal contract tests подменяли API-ответы** и проверяли UI-команды, потерянный ответ/повтор, обновление версии, роли, скачивание и размеры 320/390/1366. Они сами по себе не подтверждают backend-переходы. В targeted наборе один отдельный real information working-copy сценарий был исключён; полный frontend suite не заявляется.

После обновления чистого клона до `0fbf5a5` backend и frontend пересобраны. Отдельный настоящий Chromium-проход использовал две изолированные сессии и реальные HTTP-запросы **без подмены API**:

- Сотрудник подготовил оформление, клиент скачал Markdown, отметил обязательное согласие и подтвердил условия, сотрудник завершил действие через диалог.
- API сохранил `completed` и согласованные 2 000 000 ₽ / 24 месяца.
- Открыты реальные завершённые карточки лимита и гарантии с соответствующими подписями.
- В viewport 390 не было горизонтального переполнения; ошибок `pageerror` не было. Скриншоты просмотрены.

Этот проход не является ручной проверкой каждого продукта и исхода во всех браузерах. 390px — эмуляция viewport, а не физическое мобильное устройство.

## Живые вызовы LLM

Проверен профиль `openai / https://polza.ai/api/v1 / deepseek/deepseek-v4-flash`, `json_object`, 2048 output tokens, timeout 60 с, reasoning=false, тарифные потолки 15/25 ₽ за миллион входных/выходных токенов. Ключ не публикуется. [Настройка со своим ключом](assistant.md#настройка-проверенного-профиля).

Несколько синтетических проб охватили intake, чат и сводку. Чат верно описал завершённую сделку 500 000 ₽ / 12 месяцев и сослался на Deal. Intake распознал оборудование, 2 млн ₽ и два года как 24 месяца, но оставил purpose пустым без достаточной цитаты. Последняя сводка на `0fbf5a5` сохранила пять разделов, симуляторы и результат оформления; стоимость финансирования 67 357,60 ₽ отличена от общей выплаты 567 357,60 ₽. После изменения инструкции старый кеш отсутствовал; повтор новой сводки вернул идентичный объект.

Смысловая ошибка осталась: цель 90+ дней просрочки в течение 12 месяцев названа «невозвратом». Это разные события. Источники, суммы и формальные схемы не гарантируют правильную терминологию. Полный набор из 24 случаев, статистическая оценка качества и универсальная человеческая приёмка модели в рамках этих проб не выполнены. Время отдельных запросов не является benchmark.

## Как повторить проверки

Используйте отдельный локальный Compose-проект и синтетические данные. Сначала выполните [запуск и seed](../README.md#запуск-с-нуля), затем пройдите [сценарии](demo-scenarios.md). Backend-тесты создают/удаляют собственные временные базы; пользователь PostgreSQL должен иметь `CREATEDB`, как в локальном Compose.

```sh
docker compose run --rm backend uv run pytest -q
docker compose exec backend uv run alembic check
```

Frontend из отдельного терминала; нужны Node.js/npm и запущенный кабинет:

```sh
cd frontend
npm ci
npm run build
npx playwright install chromium
BASE_URL=http://localhost:8080 npm run test:e2e
```

Укажите фактический `DEMO_PASSWORD` существующих demo-аккаунтов, если меняли пример. E2E создают данные; не запускайте их на рабочем публичном стенде. В suite есть UI contract тесты с подменой API и проверки с реальным backend — учитывайте это при интерпретации результатов. Команды выше описывают повтор, а не новый зафиксированный прогон.

Для полного offline ML suite нужен отдельный образ:

```sh
docker compose build --build-arg INSTALL_ML=true backend
docker compose run --rm backend uv run --extra ml pytest -q
docker compose build --build-arg INSTALL_ML=false backend
```

Parity экспорта отдельно требует readonly-путей принятых данных/run через `RISK_RUNTIME_DATA` и `RISK_RUNTIME_RUN`; без них проверка явно пропускается. Публичный отобранный пакет не заменяет эти полные входы. Команды нового эксперимента — в [ML-инструкции](ml-training.md#запуск-обучения-без-бд-и-http-сервера), оценка LLM — в [инструкции помощника](assistant.md#воспроизводимая-оценка).
