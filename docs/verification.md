## Чистый Docker и настоящий API

Отдельный клон содержал только отслеживаемые файлы. В нём отсутствовали локальные artifacts обучения, личные environment-файлы и node_modules. Использовались новые PostgreSQL/document тома и собственный Compose-проект. JSON выбранной модели вошёл в обычный образ; build, автоматические миграции, up и seed завершились успешно. При сборке использовался кеш слоёв Docker: скачивание всех пакетов заново и build без кеша не проверялись.

Через nginx, API, worker и PostgreSQL пройдены восемь случаев:

1. Все шесть продуктов: одобрение с ручным решением там, где оно требуется, подготовка, подтверждение клиента и завершение сотрудником.
2. Меньшее принятое предложение: запрос 5 млн ₽ заменён согласованными 1 млн ₽ / 24 месяца; Deal сохранил именно эти условия.
3. Отмена незавершённого оформления.

Повтор команды с тем же ключом вернул прежний результат без дублирования истории. Компания другого клиента не смогла скачать условия. После полной остановки и запуска Compose сохранились все восемь сделок, версии, сгенерированные условия и SHA загруженных PNG. Это технические синтетические файлы; достоверность финансового содержимого не оценивалась.

С отключённым LLM chat вернул ожидаемый 503, а карточка и завершённая сделка оставались доступны. Это проверка необязательности помощника, а не успешный ответ без провайдера.

После изменения инструкции старый кеш отсутствовал; повтор новой сводки вернул идентичный объект.

В исторической сводке на `0fbf5a5` найдены две смысловые ошибки: цель 90 дней просрочки названа «невозвратом», а отсутствие ликвидации распространено на банкротство, которого нет в данных симулятора. На `c2a0f07` источник и SYSTEM уточняют точное событие в первые 12 календарных месяцев после предполагаемой выдачи, включая последующее полное погашение, синтетическое происхождение оценки и ограничение реестра датой регистрации и признаком ликвидации. Неизвестная цель не получает выдуманного определения, отсутствующие проверки и вероятности не превращаются в благоприятные результаты.

Целевой прогон `test_assistant_summary.py` и `test_assistant_presentation.py` на этих исходниках: **49 passed, 1 warning in 46.52s**. Использованы подменный провайдер, `LLM_PROVIDER=disabled` и отдельная случайная PostgreSQL-база тестов; проверены успешная/неприменимая/отсутствующая оценка, неизвестные цель/горизонт, реестр с обоими значениями ликвидации и без результата, инвалидация кеша при смене SYSTEM и определения. Полный backend suite и UI-проход после этой правки не повторялись; четыре перевода комментариев не меняют интерфейс.

После пересборки `c2a0f07` 26.10.2026 выполнена одна новая живая генерация (ответ сохранён в 10:51 UTC). В ней риск назван «вероятностью достижения 90 дней просрочки в первые 12 месяцев после выдачи — 3,62%» с явной пометкой синтетических данных. Реестр описан как отсутствие признака ликвидации; прочие юридические признаки не проверялись, результат неизвестен. В этой пробе обе прежние смысловые подмены не повторились. Сохранены пять разделов, завершённое оформление 500 000 ₽ / 12 месяцев и различие стоимости финансирования 67 357,60 ₽ и общей выплаты 567 357,60 ₽. По проверке координатора старый кеш после смены источников/инструкции вернул `null`, повтор после генерации — идентичный объект без новой генерации. Источники, суммы и формальные схемы не гарантируют правильную терминологию. Полный набор из 24 случаев, статистическая оценка качества и универсальная человеческая приёмка модели в рамках этих проб не выполнены. Время отдельных запросов не является benchmark.

## Как повторить проверки

Используйте отдельный локальный Compose-проект и синтетические данные. Сначала выполните [запуск и seed](../README.md#запуск-с-нуля), затем пройдите [сценарии](demo-scenarios.md). Backend-тесты создают/удаляют собственные временные базы; пользователь PostgreSQL должен иметь `CREATEDB`, как в локальном Compose.

```sh
docker compose run --rm backend uv run pytest -q
docker compose exec backend uv run alembic check
```

Frontend из отдельного терминала; нужны Node.js/npm и запущенный кабинет:

```sh
cd frontend
npm ci
npm run build
npx playwright install chromium
BASE_URL=http://localhost:8080 npm run test:e2e
```

Укажите фактический `DEMO_PASSWORD` существующих demo-аккаунтов, если меняли пример. E2E создают данные; не запускайте их на рабочем публичном стенде. В suite есть UI contract тесты с подменой API и проверки с реальным backend — учитывайте это при интерпретации результатов. Команды выше описывают повтор, а не новый зафиксированный прогон.

Для полного offline ML suite нужен отдельный образ:

```sh
docker compose build --build-arg INSTALL_ML=true backend
docker compose run --rm backend uv run --extra ml pytest -q
docker compose build --build-arg INSTALL_ML=false backend
```

Parity экспорта отдельно требует readonly-путей принятых данных/run через `RISK_RUNTIME_DATA` и `RISK_RUNTIME_RUN`; без них проверка явно пропускается. Публичный отобранный пакет не заменяет эти полные входы. Команды нового эксперимента — в [ML-инструкции](ml-training.md#запуск-обучения-без-бд-и-http-сервера), оценка LLM — в [инструкции помощника](assistant.md#воспроизводимая-оценка).

## Переход на единый Caddy, 26.10.2026

Конфигурация веб-сервера проверена отдельно после основной приёмки: один образ `frontend` на Caddy обслуживает React и проксирует API. В изолированном Compose-проекте прошли HTTP и HTTPS проверки настоящих запросов: SPA-маршруты, JavaScript и gzip, JSON-ошибки API вместо HTML, вход клиента и сотрудника, HttpOnly/SameSite/Secure-cookie, CSRF, создание черновика и загрузка/скачивание PDF с совпадением SHA-256. HTTPS использовал отдельный тестовый CA, которому доверял только проверочный клиент; проверка TLS не отключалась. Caddy сохранил HTTPS-схему при входящем поддельном X-Forwarded-Proto.

Развёрнутая Compose-конфигурация проверена на три основных сервиса, только порты 80/443 у frontend, отсутствие внешних портов API/БД и сохранение имён томов сертификатов. `Caddy validate` и сборка frontend (TypeScript/Vite внутри Docker) прошли; nginx в образе отсутствует. Backend использован из ранее проверенного образа с теми же исходниками; его код и схема БД в этом переходе не менялись. Полные прикладные и модельные наборы тестов повторно не запускались. Проверка тестового HTTPS сама по себе не подтверждает обновление публичного VPS.

После публикации `f889093` изменённый frontend собран непосредственно на VPS и получил порты 80/443. Через публичный домен повторно проверены перенаправление HTTP → HTTPS, SPA и JavaScript, вход клиента/сотрудника, сохранность всех 15 клиентских заявок и неизменность семи Deal-состояний/версий. Ранее загруженный PDF совпал по SHA-256; сохранённая сводка прочитана без нового LLM-вызова. Backend и БД при этом не пересоздавались. Это проверка конкретного обновления, а не нагрузочный тест или репетиция восстановления.
