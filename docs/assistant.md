# Помощник кредитного кабинета

Помощник разбирает описание потребности, отвечает по справочнику с источниками и составляет сводку сотруднику. LLM полезна для языка и краткого пересказа; финансовые расчёты, риск, решения и оформление выполняет код. Помощник не отправляет заявку, не подтверждает условия, не читает содержимое вложений и не заменяет сотрудника.

По умолчанию `LLM_PROVIDER=disabled`. Форма, документы, рассмотрение и оформление работают без LLM; помощник сообщает о недоступности. Внешний провайдер, ключ и квота нужны только для его включения. Веса LLM в репозиторий и образы не входят.

## Три пользовательских сценария

| Сценарий | Как пользоваться | Ограничение |
| --- | --- | --- |
| Разобрать потребность | В новой форме описать цель, сумму и срок; проверить предложенные поля и явно применить их | Backend сверяет цитаты, типы и диапазоны. Неоднозначные или неподтверждённые поля остаются пустыми для ручного уточнения |
| Задать вопрос | На списке спросить о продуктах; для своей суммы, статуса и следующего шага открыть карточку заявки | Справочный чат не открывает чужую заявку по введённому номеру |
| Получить сводку | Сотруднику открыть карточку, сформировать сводку, при необходимости обновить и скачать Markdown | Пять разделов пересказывают источники, но не являются кредитным решением |

Сводка разделена на запрос клиента, финансы, проверки и документы, расчёт и риск, результат и следующий шаг. Суммы показываются в рублях; хранение и API используют копейки. Стоимость финансирования и общая выплата — разные поля; ПСК кабинет не рассчитывает.

После подготовки оформления чат и сводка получают отдельный источник Deal: окончательные условия, состояние и доступные действия. После `completed` помощник должен описывать уже завершённый демонстрационный результат, после `cancelled` — отмену, без повторного согласия или обещания банковского перевода. Исторический запрос уточнений отозванной заявки остаётся в истории, но не предлагается как активный шаг.

## Как устроен RAG

Перед ответом сервер выполняет полнотекстовый поиск PostgreSQL с русской конфигурацией по версионированному справочнику продуктов, документов, статусов и терминов. Находит до пяти фрагментов и при вопросе о заявке добавляет актуальный разрешённый контекст. Это retrieval без embeddings и векторной БД, а не обучение модели на документах кабинета.

Одна БД упрощает поставку и обновление справочника. Компромисс — качество поиска зависит от формулировок и покрытия справочника; семантический поиск отдельной моделью не реализован. При отсутствии релевантного контекста возвращается недостаток сведений. Найденный источник не гарантирует, что LLM правильно его перескажет.

Клиентский чат получает сведения своей компании; сотруднику доступны внутренние проверки и риск. На каждом запросе собираются свежие факты версии заявки. Название продукта берётся из закреплённого каталога и имеет приоритет над общим описанием других продуктов. Перед выдачей ответа сервер снова проверяет сессию, роль, доступ, версию и допустимость идентификаторов источников. Техническая валидация цитаты подтверждает связь с переданным источником, но не доказывает смысловую верность текста.

## История диалога и кеш сводки

Виджет сохраняет ленту при закрытии и открытии. Перезагрузка, смена пользователя, заявки или её версии начинают новый диалог. «Новый диалог» очищает ленту и черновик и отменяет активный запрос; запоздалый ответ скрывается. После ошибки «Повторить вопрос» заменяет ошибочную реплику, сохраняя следующий черновик.

Чат заявки отправляет до шести завершённых пар `{question, answer, status?}`: вопрос до 2000, ответ до 6000 Unicode codepoints, общий предел 12000. Статус `answered|insufficient_context` по умолчанию `answered`. При переполнении исключаются целые старые пары; транспортные ошибки и незавершённые ответы не передаются. История разрешена только с `application_id` и `expected_version`; в справочном чате списка она не отправляется.

История — отдельное недоверенное JSON-поле, помогающее понять «А почему?» и «Что дальше?». Ответы из неё не становятся финансовыми фактами или источниками. `insufficient_context` сохраняет границу темы; явный вопрос о заявке возвращает её актуальный контекст. Переписка хранится в памяти виджета, а не в БД.

Успешная сводка после серверной валидации сохраняется в БД. GET возвращает актуальный кеш или `null` без вызова модели; POST повторно использует актуальный результат, а «Обновить сводку» явно запрашивает новый. Изменение заявки, результатов проверок, оформления, модели или инструкции меняет fingerprint и делает прежнюю сводку неактуальной. Ошибка обновления не заменяет сохранённый ответ. Markdown содержит текст и источники.

## Настройка проверенного профиля

26.10.2026 ограниченная живая проверка выполнена с `openai` / Польза AI / `deepseek/deepseek-v4-flash`, в режиме `json_object`. Результаты и выявленные ошибки описаны [ниже](#что-фактически-проверено). Это конкретный профиль, а не гарантия совместимости произвольной модели.

Создайте закрытый файл `.env.llm` в корне проекта и сохраните в нём только настройки LLM, подставив **свой ключ Польза AI**:

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://polza.ai/api/v1
LLM_MODEL=deepseek/deepseek-v4-flash
LLM_API_KEY=<ваш ключ Польза AI>
LLM_JSON_MODE=json_object
LLM_REASONING_ENABLED=false
LLM_MAX_TOKENS=2048
LLM_TIMEOUT_SECONDS=60
LLM_POLZA_MAX_PROMPT_RUB=15
LLM_POLZA_MAX_COMPLETION_RUB=25
```

Из корня уже запущенного локального проекта:

```sh
chmod 600 .env.llm
docker compose --env-file .env --env-file .env.llm up -d --no-deps --force-recreate --wait backend
```

Второй файл имеет приоритет над `.env`; обычный `restart` не перечитывает Compose-переменные. Если менялся код, сначала выполните сборку по [README](../README.md#запуск-с-нуля). Ключ остаётся в backend, не передаётся браузеру и не должен попадать в Git или отчёт. Для HTTPS используйте то же сочетание environment-файлов с [серверным Compose](deployment.md), сохраняя имя действующего проекта.

`LLM_POLZA_MAX_PROMPT_RUB` и `LLM_POLZA_MAX_COMPLETION_RUB` — потолки тарифа в ₽ за миллион входных/выходных токенов, **не общий бюджет**. Backend передаёт их в `provider.max_price`, ограничивает фиксированную цену запроса нулём и запрещает fallback. При нулевых потолках вызовы Польза AI отключены. Нужны точный HTTPS endpoint и непустой ключ; алиасы с `@` не допускаются. Расход и баланс контролируются у провайдера. Ограничения реализуются провайдером; тест контракта не подтверждает фактическое списание.

Наличие ключа не гарантирует квоту, поддержку формата, доступность или правильность ответа. Вызов ограничен таймаутом, размером ответа и двумя одновременными запросами на процесс. Автоматических повторов и скрытой смены провайдера нет. При 429, транспортной ошибке, неверном JSON или недопустимых источниках кабинет возвращает безопасную техническую недоступность, не выдавая сырой ответ провайдера; состояние заявки не меняется.

## Другие провайдеры

Для произвольного OpenAI-совместимого API задаются `LLM_PROVIDER=openai`, точный `LLM_BASE_URL`, модель и свой ключ. `json_schema` передаёт строгую схему; `json_object` помещает схему в инструкцию. Оба проходят серверную валидацию. Поддержку конкретной моделью проверяют отдельно.

OpenRouter разрешён только с `https://openrouter.ai/api/v1` и моделью с `:free`. Backend передаёт нулевые потолки prompt/completion/request, `allow_fallbacks=false` и `LLM_DATA_COLLECTION=deny` по умолчанию; `allow` явно разрешает провайдеров, сохраняющих запросы. Бесплатная квота, лицензия весов и качество не следуют из суффикса `:free`. Этот параметр хранения не управляет Польза AI.

Пустой `LLM_REASONING_ENABLED` не передаёт параметр; явные `true/false` передаются OpenRouter и Польза AI. Иные совместимые API используют контракт без него. Совместимость транспорта не является содержательной приёмкой модели.

## Локальный Ollama

Необязательный Compose-профиль запускает Ollama во внутренней сети без публикации порта 11434:

```sh
docker compose --profile ollama up -d ollama
docker compose exec ollama ollama pull qwen3:8b
```

Задайте в environment-файле `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://ollama:11434`, `LLM_MODEL=qwen3:8b` и пересоздайте backend. API-ключ не нужен. Веса и образ загружаются отдельно; RAM, скорость, лицензия и качество этого локального профиля текущей приёмкой не проверены. По умолчанию образ использует `latest`; для собственной повторяемой поставки задайте проверенный `OLLAMA_IMAGE`.

Если Ollama уже работает на хосте, можно использовать `http://host.docker.internal:11434`; сервис должен слушать доступный контейнеру адрес. Не публикуйте LLM-порт в интернете. Основной кабинет после сборки не зависит от внешнего LLM, но поставка с полностью подготовленными образами и весами для компьютера без сети не предоставляется.

## Что фактически проверено

На профиле выше проверены разбор потребности, чат завершённой заявки и сводка сотруднику. Чат верно назвал 500 000 ₽ / 12 месяцев, завершение и источник Deal. Разбор «Купить хорошо бы две печи за два ляма, кредит на два года» дал оборудование, 2 000 000 ₽ и 24 месяца; purpose остался пустым, поскольку не подтвердился цитатой. Это предусмотренный переход к ручному уточнению, а не безошибочное извлечение всех полей.

Историческая сводка на `0fbf5a5` сохранила пять разделов, назвала проверки симуляторами и отделила стоимость финансирования 67 357,60 ₽ от общей выплаты 567 357,60 ₽. После изменения инструкции старый кеш не выдавался, повтор новой сводки возвращал тот же объект.

**Исторические содержательные ошибки:** сводка на `0fbf5a5` назвала риск «невозвратом в течение 12 месяцев» и приписала реестровому симулятору отсутствие банкротства. Цель модели — достижение 90 дней просрочки в первые 12 календарных месяцев после предполагаемой выдачи, включая последующее полное погашение. Реестровый симулятор сообщает дату регистрации и признак ликвидации; банкротство и исполнительные производства не проверяются.

На `c2a0f07` источник и инструкция сводки уточнены: известная цель получает явное русское определение и пометку синтетического происхождения; неизвестная цель или горизонт остаются без определения. Отсутствующая или неприменимая оценка не получает вероятности. Реестровый источник явно ограничивает охват, остальные юридические признаки остаются неизвестными. Контракт источников и инвалидация кеша проверены с подменным провайдером: **49 targeted tests passed**. Это не проверка произвольного ответа внешней LLM.

После пересборки `c2a0f07` 26.10.2026 выполнена одна новая живая генерация (ответ сохранён в 10:51 UTC). В ней риск назван «вероятностью достижения 90 дней просрочки в первые 12 месяцев после выдачи — 3,62%» с явной пометкой синтетических данных. Реестр описан как отсутствие признака ликвидации; прочие юридические признаки не проверялись, результат неизвестен. В этой пробе обе прежние смысловые подмены не повторились. Сохранены пять разделов, завершённое оформление 500 000 ₽ / 12 месяцев и различие стоимости финансирования 67 357,60 ₽ и общей выплаты 567 357,60 ₽. По проверке координатора старый кеш после смены источников/инструкции вернул `null`, повтор после генерации — идентичный объект без новой генерации. Это наблюдение одного синтетического сценария, а не гарантия точности остальных ответов.

Значение и определение риска сверяйте с карточкой оценки. Несколько живых проб подтверждают отдельные сценарии и доступность профиля, но не дают статистической оценки качества и не являются полной человеческой приёмкой всех ответов.

При `LLM_PROVIDER=disabled` chat вернул предусмотренный 503, а карточка и завершённая сделка оставались доступны. Подробная версия и границы остальных проверок — в [verification](verification.md).

## Воспроизводимая оценка

Набор содержит 24 русских случая: 8 разборов, 10 вопросов и 6 сводок. Это отдельная оценка; при описанной выше ограниченной живой приёмке полный набор не запускался. Скрипт использует настоящий провайдер и PostgreSQL-поиск, но синтетические Source-снимки; он не проверяет авторизацию API или выбор актуальных ORM-данных.

Подготовьте на хосте Python 3.12, uv и отдельную PostgreSQL-базу. Из корня выполните `cd backend`, `uv sync --frozen`, затем вернитесь в корень. Передайте `DATABASE_URL`, `DEMO_PASSWORD` и `LLM_*` через окружение: скрипт не загружает environment-файл сам. Миграции для поиска по справочнику не нужны; реальные заявки не читаются.

```sh
backend/.venv/bin/python backend/scripts/evaluate_assistant.py \
  --dataset backend/tests/fixtures/assistant_eval.json \
  --output-dir /tmp/assistant-evaluation
```

На случай делается максимум один вызов без повторов. Ошибка авторизации, квоты или транспорта останавливает прогон; оставшиеся случаи отмечаются непроверенными. Неверный JSON — ошибка отдельного случая. JSON/Markdown отчёты содержат модель, digest набора, версию кода, длительности, ошибки и ссылки. Для смыслового ревью фиксированных синтетических примеров есть `--include-synthetic-responses`; обычный режим не сохраняет ответы.

Схема и допустимые ссылки проверяются автоматически; факты, терминология и полезность требуют отдельного содержательного чтения. Ответ помощника всегда следует сверять с источниками и решением сотрудника.
