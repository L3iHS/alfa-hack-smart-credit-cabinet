# Помощник кредитного кабинета

Помощник предлагает поля по описанию потребности, отвечает по справочнику с источниками и составляет фактологическую сводку сотруднику. Он не принимает решения, не отправляет заявку, не рассчитывает риск и не читает содержимое вложений. Предложенные поля применяет клиент после проверки.

В чате сохраняется лента вопросов и ответов; у каждого ответа свои источники. Можно подготовить следующий вопрос, пока формируется ответ. После ошибки «Повторить вопрос» обновляет именно ошибочную реплику и сохраняет новый черновик. При повторе используются только успешные пары до неё, без более поздних сообщений. Закрытие и открытие виджета сохраняет ленту; перезагрузка страницы, смена пользователя, заявки или версии начинает новый диалог. «Новый диалог» очищает ленту и черновик и отменяет активный запрос; запоздалый ответ скрывается. В карточке заявки сервер принимает короткую историю для уточнений «А почему?», «Подробнее» и «Что дальше?». Ответы поддерживают абзацы, заголовки, списки и выделение; сводка сотруднику разделена на запрос клиента, финансы, проверки и документы, расчёт и риск, результат и следующий шаг.

По умолчанию `LLM_PROVIDER=disabled`. Обычная форма, сведения о заявке и кредитный процесс работают без LLM; при отключении или сбое помощник сообщает о недоступности. Секреты задаются только в локальном environment-файле или окружении; не добавляйте ключ в Git, браузерный код или отчёты. После изменения конфигурации пересоздайте backend.

На странице списка помощник отвечает по справочнику. Для вопроса о сумме, условиях или статусе конкретной заявки откройте её карточку: в заголовке помощника появится номер заявки. Данные берутся из разрешённой пользователю заявки; ввод произвольного номера в справочном чате не открывает другую заявку. RAG ищет нужные фрагменты перед каждым ответом, а не обучает модель на данных кабинета. Подбор продукта выполняется отдельно по правилам каталога и финансовым расчётам.

API чата принимает необязательное поле `history`: до 6 завершённых пар `{question, answer, status?}`, вопрос до 2000, ответ до 6000 Unicode codepoints, суммарно до 12000. Необязательный `status` принимает `answered|insufficient_context`, по умолчанию `answered` для прежних клиентов. Пустые реплики, дополнительные поля (включая роли и источники) и неверные типы отклоняются. Непустая история допустима только с `application_id` и `expected_version`; прежние запросы без истории совместимы. Сервер не сохраняет переписку в БД и не меняет бизнес-данные при чтении.

Браузер отправляет последние 6 завершённых пар текущей заявки. `insufficient_context` передаётся с явным статусом как граница темы, без подтверждённых сведений. Ошибки транспорта, незавершённые ответы и пары сверх индивидуальных пределов исключаются; при превышении 12000 символов исключаются целые старые пары. В справочном чате списка история не отправляется.

Название выбранного продукта передаётся в данных заявки из её закреплённой версии каталога. Эти данные имеют приоритет над общими описаниями других продуктов; история помогает понять короткое уточнение, но не подтверждает финансовые факты. Прежняя ошибка исправляется по свежим источникам. Посторонний вопрос с `insufficient_context` сохраняет границу темы для «А почему?» и «Что дальше?»; явный новый вопрос о заявке возвращает её контекст.

История передаётся модели отдельным недоверенным JSON-полем. Она помогает понять предмет короткого продолжения; для поиска используется ближайший самостоятельный предыдущий вопрос, без объединения всех прошлых тем и без использования ответов как поисковых фактов. Явно новый вопрос задаёт новый предмет. На каждом обращении сервер заново собирает разрешённые источники текущей версии заявки, выполняет один поиск по справочнику с лимитом 5 источников и добавляет релевантный снимок заявки. Только эти свежие источники подтверждают суммы, условия, статус и действия. Идентификаторы из старого текста не становятся допустимыми цитатами. После генерации сервер повторно проверяет сессию, роль, доступ и версию, затем проверяет цитаты; эти проверки действуют и при недостатке источников.

После отзыва заявки рассмотрение прекращено. Прежний открытый запрос уточнений остаётся в истории заявки, но исключается из активных источников помощника и не предлагает отправить ответ или загрузить документы.

Сводка сотруднику сохраняется в базе. Возвращение в карточку загружает актуальную сводку без вызова модели; «Обновить сводку» явно запрашивает новую. Изменение заявки, результатов проверок, модели или инструкции делает прежний результат неактуальным. Сводку с источниками можно скачать в Markdown. Она не является кредитным решением. Деньги в ответах и источниках показаны в рублях; точное хранение и API по-прежнему используют копейки.

## OpenAI-совместимый API

Настройте переменные из `.env.example` (для серверного Compose — из `.env.deploy.example`):

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=<точный идентификатор открытой модели с суффиксом :free>
LLM_API_KEY=<ваш ключ>
LLM_TIMEOUT_SECONDS=45
LLM_MAX_TOKENS=1200
LLM_JSON_MODE=json_schema
LLM_REASONING_ENABLED=false
LLM_DATA_COLLECTION=deny
```

Для OpenRouter backend разрешает только HTTPS, точный endpoint и модель `:free`; передаёт нулевую максимальную цену для prompt/completion/request, `allow_fallbacks=false` и `data_collection` из `LLM_DATA_COLLECTION` (по умолчанию `deny`). Бесплатные квоты и доступность не гарантируются; backend не переключается на платную модель. Указание `:free` само по себе не подтверждает лицензию весов: проверяйте лицензию выбранной модели отдельно.

`LLM_JSON_MODE=json_schema` передаёт строгую JSON-схему. `json_object` добавляет схему в системную инструкцию и всё равно проходит те же серверные проверки ответа. Пустое `LLM_REASONING_ENABLED` сохраняет поведение провайдера; явные `true`/`false` отправляются OpenRouter и Польза AI. Остальные совместимые API используют тот же контракт без этого параметра. Ошибка формата, источников или транспорта возвращает безопасную техническую ошибку без ответа провайдера.

## Смена модели через environment-файл

Для синтетического стенда можно явно разрешить провайдеров, сохраняющих запросы и ответы: `LLM_DATA_COLLECTION=allow`. Это требуется некоторым бесплатным NVIDIA-провайдерам OpenRouter. Значение `deny` сохраняет исходное ограничение; другие значения не допускаются. Параметр относится только к OpenRouter, не меняет его квоты и не разрешает платные вызовы.

Пример настройки для проб Nemotron Ultra (сохраните свой существующий `LLM_API_KEY`):

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=nvidia/nemotron-3-ultra-550b-a55b:free
LLM_DATA_COLLECTION=allow
LLM_JSON_MODE=json_object
LLM_REASONING_ENABLED=true
LLM_MAX_TOKENS=4096
LLM_TIMEOUT_SECONDS=120
```

Для другой модели замените `LLM_MODEL` точным ID из OpenRouter с суффиксом `:free`. Код под каждую модель менять не нужно, но поддержка JSON-схемы и reasoning различается: `json_object` служит альтернативой `json_schema`, пустое `LLM_REASONING_ENABLED` оставляет выбор провайдеру. Доступность в каталоге не гарантирует свободную квоту или качество ответа.

## Польза AI: платная модель с ограничением тарифа

Для разработки можно подключить модель через [Польза AI](https://polza.ai/models/deepseek/deepseek-v4.1-flash-1017). Используйте отдельный ключ этого сервиса; ключ OpenRouter сюда не подходит. Допустимость платного API для сдачи определяется правилами мероприятия отдельно от технической совместимости.

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://polza.ai/api/v1
LLM_MODEL=deepseek/deepseek-v4.1-flash-1017
LLM_API_KEY=<ключ Польза AI>
LLM_JSON_MODE=json_object
LLM_REASONING_ENABLED=false
LLM_MAX_TOKENS=2048
LLM_TIMEOUT_SECONDS=60
LLM_POLZA_MAX_PROMPT_RUB=15
LLM_POLZA_MAX_COMPLETION_RUB=25
```

`LLM_POLZA_MAX_PROMPT_RUB` и `LLM_POLZA_MAX_COMPLETION_RUB` — максимальный тариф в рублях за миллион входных и выходных токенов. Backend передаёт эти ограничения в `provider.max_price`, выбирает по цене и запрещает fallback. Отдельный фиксированный тариф за запрос ограничен нулём (`request=0`); это не ограничение полной стоимости запроса. Единицы и поля описаны в [документации маршрутизации Польза AI](https://polza.ai/docs/gaidy/provider-selection).

По умолчанию оба потолка равны нулю: вызовы Польза AI отключены до явной настройки. Нужен точный HTTPS endpoint выше и непустой ключ. Алиасы с параметрами через `@` в имени модели не допускаются, чтобы они не переопределяли маршрутизацию. `LLM_DATA_COLLECTION` относится только к OpenRouter и не управляет хранением данных в Польза AI.

**Это потолок тарифа, а не общий бюджет.** Ограничение длины ответа и отсутствие автоматических повторов уменьшают расход одного обращения, но число обращений не ограничивают. Расход и оставшийся баланс контролируются в кабинете провайдера. При изменении тарифа сверх потолка помощник станет недоступен, а кредитный кабинет продолжит работать. Ограничение применяется провайдером; автоматические тесты проверяют передаваемый контракт, а не фактическое списание.

Сначала проверьте разбор потребности, ответ с источниками и сводку сотрудника на синтетических примерах. Совместимость API не гарантирует качество конкретной модели. Для переключения сохраните настройки в `.env.llm` и пересоздайте backend командами ниже. При первом переходе с версии без этих настроек требуется обновление кода и сборка backend.

После сохранения настроек пересоздайте только backend. Обычный `restart` не перечитывает Compose-переменные. При смене только настроек сборка образов и `git pull` не нужны; новое значение применяется к новым запросам, уже показанные ответы не пересчитываются.

Для стандартного локального Compose, если общие параметры находятся в `.env`, а параметры модели в `.env.llm`:

```sh
docker compose --env-file .env --env-file .env.llm up -d --no-deps --force-recreate --wait backend
```

Для VPS выполните на самом сервере, сохраняя существующие `.env.deploy` и имя Compose-проекта:

```sh
cd /srv/credit-cabinet
sudo docker compose -p credit-cabinet-vps --env-file .env.deploy --env-file .env.llm -f compose.yaml -f compose.deploy.yaml up -d --no-deps --force-recreate --wait backend
```

Параметр `-p credit-cabinet-vps` выбирает действующий серверный стенд. Его имя должно совпадать с проектом контейнеров Caddy, backend и БД. Без него при отсутствии `COMPOSE_PROJECT_NAME` может быть создан другой стенд, а сайт продолжит работать со старым backend.

Второй файл содержит только `LLM_*` и имеет приоритет над первым. Если все настройки модели записаны непосредственно в `.env.deploy`, уберите `--env-file .env.llm`. Изменение файла на ноутбуке не меняет серверный файл. Не публикуйте файлы с ключами. Команды предполагают уже собранный backend с поддержкой соответствующих параметров; после обновления кода сначала выполните обычное обновление со сборкой.

## Локальный Ollama

Необязательный профиль Compose запускает Ollama во внутренней сети без публикации порта 11434:

```sh
docker compose --profile ollama up -d ollama
docker compose exec ollama ollama pull qwen3:8b
```

Затем задайте `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://ollama:11434`, `LLM_MODEL=qwen3:8b` и пересоздайте backend: `docker compose up -d --build backend`. API-ключ не требуется. Веса загружаются отдельно; локальные память, скорость, лицензия и качество конкретной модели требуют отдельной проверки. Образ по умолчанию использует `latest`; для воспроизводимой поставки закрепите проверенный тег или digest через `OLLAMA_IMAGE`.

Если Ollama уже работает на хосте, используйте `http://host.docker.internal:11434` вместо имени сервиса. Compose добавляет Linux host-gateway; Ollama должна слушать доступный контейнеру адрес. Ограничьте доступ локальным интерфейсом/межсетевым экраном и не публикуйте LLM-порт в интернете. На macOS стандартный localhost Ollama может требовать изменения адреса прослушивания; встроенный профиль избегает этой настройки.

## Воспроизводимая оценка

Набор содержит ровно 24 русских случая: 8 разборов, 10 вопросов и 6 сводок. Скрипт запускается на хосте из корня репозитория после `cd backend && uv sync --frozen && cd ..`. Передайте `DATABASE_URL` отдельной PostgreSQL-базы, `DEMO_PASSWORD` и `LLM_*` через окружение; скрипт не загружает environment-файл самостоятельно. Миграции для поиска по справочнику не нужны; реальные заявки не читаются.

```sh
backend/.venv/bin/python backend/scripts/evaluate_assistant.py \
  --dataset backend/tests/fixtures/assistant_eval.json \
  --output-dir /tmp/assistant-evaluation
```

Это настоящий провайдер, production intake/генерация/валидация и PostgreSQL поиск, дополненные синтетическими Source-снимками. Это не прогон авторизации API и не проверка выбора актуальных данных из ORM: эти свойства отдельно покрывают backend-тесты. Последовательный прогон делает максимум один вызов на случай, без повторов; при недоступности, отказе авторизации, исчерпании квоты или транспортной ошибке останавливается и отмечает оставшиеся случаи как непроверенные. Некорректный JSON регистрируется как ошибка отдельного случая; следующий случай выполняется без повтора предыдущего.

JSON и Markdown включают модель, digest набора, версию кода, длительности (p50/p95 nearest-rank), ошибки и ссылки. По умолчанию ответы не сохраняются; для содержательного ревью только фиксированных синтетических примеров добавьте `--include-synthetic-responses`. Не используйте эту опцию для пользовательских данных. Автоматические проверки полей и источников отделены от смыслового ревью: успешная схема не подтверждает правильность фактов. Итоговую приёмку проводит человек; оценки другого агента должны явно обозначаться как такие.

## Текущее состояние проверки

24.10.2026 выполнены реальные пробы `dots-studio/dots-3-note-preview:free` через OpenRouter: получены структурированные ответы и проверен транспорт, но также зафиксированы HTTP 400 и некорректный JSON. Содержательная проверка выявила ошибки пересказа: смешение отчётного периода со сроком кредита, платежей с остатком долга и неверное описание неприменимости модели как технического сбоя. Инструкции уточнены; повторные сводки всё ещё содержат ошибки и пропуски, человеческая приёмка не пройдена. Кандидат не принят для демонстрации сводок; готовность выбранной модели не заявляется.

По умолчанию помощник остаётся выключенным (`LLM_PROVIDER=disabled`). При его использовании интерфейс показывает отдельные источники, с которыми пользователь может сверить факты; ответ модели не заменяет данные заявки и решение банка.
