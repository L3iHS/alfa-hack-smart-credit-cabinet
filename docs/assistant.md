# Помощник кредитного кабинета

Помощник предлагает поля по описанию потребности, отвечает по справочнику с источниками и составляет фактологическую сводку сотруднику. Он не принимает решения, не отправляет заявку, не рассчитывает риск и не читает содержимое вложений. Предложенные поля применяет клиент после проверки.

По умолчанию `LLM_PROVIDER=disabled`. Обычная форма, сведения о заявке и кредитный процесс работают без LLM; при отключении или сбое помощник сообщает о недоступности. Секреты задаются только в локальном environment-файле или окружении; не добавляйте ключ в Git, браузерный код или отчёты. После изменения конфигурации пересоздайте backend.

## OpenAI-совместимый API

Настройте переменные из `.env.example` (для серверного Compose — из `.env.deploy.example`):

```dotenv
LLM_PROVIDER=openai
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=<точный идентификатор открытой модели с суффиксом :free>
LLM_API_KEY=<ваш ключ>
LLM_TIMEOUT_SECONDS=45
LLM_MAX_TOKENS=1200
LLM_JSON_MODE=json_schema
LLM_REASONING_ENABLED=false
```

Для OpenRouter backend разрешает только HTTPS, точный endpoint и модель `:free`; передаёт нулевую максимальную цену для prompt/completion/request, `allow_fallbacks=false` и `data_collection=deny`. Бесплатные квоты и доступность не гарантируются; backend не переключается на платную модель. Указание `:free` само по себе не подтверждает лицензию весов: проверяйте лицензию выбранной модели отдельно.

`LLM_JSON_MODE=json_schema` передаёт строгую JSON-схему. `json_object` добавляет схему в системную инструкцию и всё равно проходит те же серверные проверки ответа. Пустое `LLM_REASONING_ENABLED` сохраняет поведение провайдера; явные `true`/`false` отправляются только OpenRouter. Другие совместимые API используют тот же контракт без этого параметра. Ошибка формата, источников или транспорта возвращает безопасную техническую ошибку без ответа провайдера.

## Локальный Ollama

Необязательный профиль Compose запускает Ollama во внутренней сети без публикации порта 11434:

```sh
docker compose --profile ollama up -d ollama
docker compose exec ollama ollama pull qwen3:8b
```

Затем задайте `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://ollama:11434`, `LLM_MODEL=qwen3:8b` и пересоздайте backend: `docker compose up -d --build backend`. API-ключ не требуется. Веса загружаются отдельно; локальные память, скорость, лицензия и качество конкретной модели требуют отдельной проверки. Образ по умолчанию использует `latest`; для воспроизводимой поставки закрепите проверенный тег или digest через `OLLAMA_IMAGE`.

Если Ollama уже работает на хосте, используйте `http://host.docker.internal:11434` вместо имени сервиса. Compose добавляет Linux host-gateway; Ollama должна слушать доступный контейнеру адрес. Ограничьте доступ локальным интерфейсом/межсетевым экраном и не публикуйте LLM-порт в интернете. На macOS стандартный localhost Ollama может требовать изменения адреса прослушивания; встроенный профиль избегает этой настройки.

## Воспроизводимая оценка

Набор содержит ровно 24 русских случая: 8 разборов, 10 вопросов и 6 сводок. Скрипт запускается на хосте из корня репозитория после `cd backend && uv sync --frozen && cd ..`. Передайте `DATABASE_URL` отдельной PostgreSQL-базы, `DEMO_PASSWORD` и `LLM_*` через окружение; скрипт не загружает environment-файл самостоятельно. Миграции для поиска по справочнику не нужны; реальные заявки не читаются.

```sh
backend/.venv/bin/python backend/scripts/evaluate_assistant.py \
  --dataset backend/tests/fixtures/assistant_eval.json \
  --output-dir /tmp/assistant-evaluation
```

Это настоящий провайдер, production intake/генерация/валидация и PostgreSQL поиск, дополненные синтетическими Source-снимками. Это не прогон авторизации API и не проверка выбора актуальных данных из ORM: эти свойства отдельно покрывают backend-тесты. Последовательный прогон делает максимум один вызов на случай, без повторов; при недоступности, отказе авторизации, исчерпании квоты или транспортной ошибке останавливается и отмечает оставшиеся случаи как непроверенные. Некорректный JSON регистрируется как ошибка отдельного случая; следующий случай выполняется без повтора предыдущего.

JSON и Markdown включают модель, digest набора, версию кода, длительности (p50/p95 nearest-rank), ошибки и ссылки. По умолчанию ответы не сохраняются; для содержательного ревью только фиксированных синтетических примеров добавьте `--include-synthetic-responses`. Не используйте эту опцию для пользовательских данных. Автоматические проверки полей и источников отделены от смыслового ревью: успешная схема не подтверждает правильность фактов. Итоговую приёмку проводит человек; оценки другого агента должны явно обозначаться как такие.

## Текущее состояние проверки

24.10.2026 выполнены реальные пробы `dots-studio/dots-3-note-preview:free` через OpenRouter: получены структурированные ответы и проверен транспорт, но также зафиксированы HTTP 400 и некорректный JSON. Содержательная проверка выявила ошибки пересказа: смешение отчётного периода со сроком кредита, платежей с остатком долга и неверное описание неприменимости модели как технического сбоя. Инструкции уточнены; повторные сводки всё ещё содержат ошибки и пропуски, человеческая приёмка не пройдена. Кандидат не принят для демонстрации сводок; готовность выбранной модели не заявляется.

По умолчанию помощник остаётся выключенным (`LLM_PROVIDER=disabled`). При его использовании интерфейс показывает отдельные источники, с которыми пользователь может сверить факты; ответ модели не заменяет данные заявки и решение банка.
