# Предварительный подбор продуктов

Подбор помогает выбрать один из шести продуктов и заполнить заявку. Он не создаёт заявку, банковское предложение (`Offer`) или решение, не вызывает ML и не читает документы. Все условия демонстрационные; процента одобрения, обещания скорости и расчёта ПСК нет.

## API

- `GET /api/v1/product-recommendations/options` — публичный список целей (`purposes`: код и подпись) и `config_version`.
- `POST /api/v1/product-recommendations` — подбор; нужны сессия и CSRF. Компания клиента берётся из сессии; сотрудник указывает `?company_id=<uuid>` и дополнительно получает `staff_trace`.

Деньги — целые копейки. Финансы — суммы за один явно указанный период, отсутствующий долг не заменяется нулём. Период задаётся двумя датами завершённых полных календарных месяцев либо `period_months` от 1 до 12; эти варианты нельзя смешивать.

```json
{
  "purpose": "working_capital",
  "amount_kopecks": 300000000,
  "term_months": 12,
  "revenue_total_kopecks": 240000000,
  "expenses_total_kopecks": 120000000,
  "existing_debt_payments_kopecks": 60000000,
  "period_months": 3
}
```

В этом примере карточка `working_capital` предлагает 1 138 000 ₽ с причиной `financial_amount_adjusted`. Сумма запроса не увеличивается. Если исходная точная сумма допустима, она сохраняется; иначе выбирается максимальная допустимая сумма на сетке 1 000 ₽ в пределах запроса и каталога. Срок приводится к диапазону продукта, изменение объясняется в карточке. Это расчёт финансовой доступности, не прогноз решения.

Поля формы `revenue_kopecks` и `operating_expenses_kopecks` передаются как `revenue_total_kopecks` и `expenses_total_kopecks`; имя `existing_debt_payments_kopecks` сохраняется. Веб-форма передаёт `period_start`/`period_end`, а не неявный один месяц. Неизвестные поля, включая прежние `urgency`, `has_collateral` и отметки о документах, дают `422`.

## Ответ и применение

| `status` | Значение |
| --- | --- |
| `ok` | Первая карточка сохранила сумму и срок |
| `adjusted` | Первая карточка изменила сумму или срок |
| `request_data` | Не хватает финансового поля или периода; карточек нет |
| `no_match` | Подходящих условий нет; это не кредитный отказ |

Ответ содержит `items`, `missing_fields`, `actions`, `config_version`, `catalog_version`, `trace_id` и доступный только сотруднику `staff_trace`. `missing_fields` перечисляет точные имена входов; `actions` содержат понятные подписи и виды `request_field`, `apply_recommendation`, `change_amount`. Действие для `period_months` в веб-форме открывает выбор дат периода.

Каждая карточка содержит `recommendation_id`, `product_code`, название, `rank`, `purpose_match`, `recommended_amount_kopecks`, `term_months`, `payment_terms`, `financial_gate`, причины и требования к полям/документам. `recommendation_id` — идентификатор карточки ответа, не сохранённый `Offer`. Изменения других карточек показываются даже при общем `status=ok`.

Применение переносит точные код продукта, сумму и срок в форму. Доступны все шесть кодов: `working_capital`, `equipment`, `overdraft`, `credit_line`, `investment`, `tender_guarantee`. Изменение любого входа сбрасывает результат; поздний ответ прежнего запроса не возвращает устаревшие карточки. После подстановки клиент дополняет поля и загружает реальные файлы для отправки. Подбор сообщает требования, но не считает галочку доказательством наличия документа.

## Расчёт и порядок карточек

Цель сначала ограничивает набор продуктов. Затем используются общий каталог и те же [расчёт условий и финансовый допуск](architecture.md#расчёт-условий), что при рассмотрении и предложении сотрудника. Ликвидация и просрочка от 90 дней берутся из общих локальных симуляторов; неизвестный результат не заменяется благополучным.

Основной продукт цели идёт раньше смежного; далее — близость суммы и срока с весами 0.5/0.5, меньшая стоимость сценария относительно суммы и стабильный код продукта. Не более трёх карточек. Гарантия имеет отдельную цель и не сравнивается с кредитом как одинаковый инструмент.

| Цель `purpose` | Основные продукты | Смежные |
| --- | --- | --- |
| `working_capital` | Оборотный кредит, кредитная линия | Овердрафт |
| `cash_gap` | Овердрафт | Кредитная линия |
| `equipment` | Оборудование | Инвестиционный кредит |
| `investment`, `real_estate` | Инвестиционный кредит | — |
| `tender_guarantee` | Тендерная гарантия | — |

## Конфигурация и проверка

В `backend/config/rules` находятся ссылки на продукты (`products.yaml`), соответствие целей (`purpose_map.yaml`), веса (`ranking.yaml`) и тексты (`reasons.yaml`). Диапазоны, ставки, документы и формулы берутся из каталога, стоп-правила — из общего кредитного процесса. Конфигурация проверяется и кешируется при первом запросе; после её изменения процесс перезапускают. Ответ возвращает версии правил и каталога (сейчас `rules-2026.10.3` и `demo-v2`).

Для проверки контракта: `cd backend && uv run pytest -q tests/test_recommendations.py`; для интерфейса: `cd frontend && npx playwright test tests/recommendations.spec.ts tests/product-expansion.spec.ts`. Нужны PostgreSQL и поднятый API, как описано в [README](../README.md#проверки). [HTTP-пример](api-examples.http) использует актуальные имена полей.
