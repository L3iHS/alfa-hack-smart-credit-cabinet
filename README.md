# Умный кредитный кабинет

Проект для хакатона Альфа-Банка 2026: веб-кабинет для подачи и рассмотрения кредитных заявок малого бизнеса.

## Возможности

- Вход клиента и сотрудника с разными правами
- Каталог оборотного кредита и кредита на оборудование
- Данные компании, заполнение и сохранение неполной заявки
- Повторное открытие черновика, редактирование и история изменений
- Защита от перезаписи устаревшей версии заявки
- Отдельная очередь сотрудника; клиентские черновики в неё не попадают

Отправка на рассмотрение, загрузка документов, проверки ФНС/БКИ, кредитные решения и ML/LLM планируются следующим этапом.

## Стек

- Backend: Python, FastAPI, SQLAlchemy, Alembic
- Данные: PostgreSQL
- Frontend: React, TypeScript, Vite
- Запуск: Docker Compose

## Данные и проверки

Для демонстрации используются синтетические компании и финансовые сведения. Условия кредитования демонстрационные. Денежные значения API передаются целым числом копеек; форма отображает рубли.

## Запуск

Нужны Docker и Docker Compose. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build -d
docker compose exec backend uv run python -m app.seed
```

[Приложение](http://localhost:8080) · [Документация API](http://localhost:8080/api/v1/docs) · [OpenAPI](http://localhost:8080/api/v1/openapi.json)

При запуске backend автоматически применяет миграции. PostgreSQL хранит данные в Docker volume. Обычный перезапуск сохраняет данные и действующие серверные сессии:

```sh
docker compose restart
```

### Запуск на VPS

[Инструкция серверного запуска с HTTPS](docs/deployment.md). Конфигурация проверена локально с отдельной БД и локальным центром сертификации; публичный сертификат, DNS и запуск на VPS ещё не проверены.

### Демонстрационные учётные записи

Регистрация не требуется. После запуска seed доступны:

| Email | Роль | Компания |
| --- | --- | --- |
| `client1@example.test` | Клиент | Демо Пекарня |
| `client2@example.test` | Клиент | Демо Мастерская |
| `staff@example.test` | Сотрудник | — |

Пароль при первом заполнении — значение `DEMO_PASSWORD` из `.env` (в примере `Demo-credit-2026!`). Повторный запуск seed добавляет недостающие записи и сохраняет существующие данные и пароли.

API использует cookie сессии. Перед изменяющими запросами получите токен через `GET /api/v1/auth/csrf` и передавайте cookie и заголовок `X-CSRF-Token`. Успешный вход возвращает новый токен; прежняя сессия отзывается. Сессия действует 8 часов по умолчанию (`SESSION_TTL_SECONDS`). Для размещения за HTTPS задаётся `COOKIE_SECURE=true`.

### Проверки

```sh
docker compose run --rm backend uv run pytest -q
docker compose exec backend uv run alembic check
```

Backend-тесты используют отдельную временную базу PostgreSQL, применяют миграции и удаляют только эту тестовую базу. Для её создания пользователь PostgreSQL должен иметь право `CREATEDB`; в локальном Compose оно доступно. Данные приложения эти тесты не очищают.

Сборка и браузерные проверки требуют Node.js и запущенного приложения с демонстрационными аккаунтами:

```sh
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты работают с реальным API и создают черновики в демонстрационных аккаунтах. Если пароль изменён, передайте то же значение в переменной `DEMO_PASSWORD` при запуске тестов. Адрес приложения переопределяется переменной `BASE_URL`.
