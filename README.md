# Умный кредитный кабинет

Прототип для хакатона Альфа-Банка 2026: подача и рассмотрение кредитных заявок малого бизнеса в одном веб-кабинете.

Клиент выбирает оборотный кредит или кредит на оборудование, сохраняет черновик, прикладывает документы и отправляет заявку. Кабинет показывает результат проверки, запрос уточнений или предложение других условий. Сотрудник видит очередь, результаты проверок, расчёт нагрузки и историю; может запросить сведения, предложить условия, одобрить или отклонить заявку с причиной.

Все компании, финансовые сведения и внешние проверки синтетические. Обученная LogisticRegression `logistic-risk-v1` оценивает достижение 90 дней просрочки по рассматриваемому кредиту за первые 12 календарных месяцев после предполагаемой выдачи. Политика `demo-policy-0.3` использует этот риск в решении: p < 0.10 допускает автоматическое одобрение при K ≥ 1.30 и остальных проверках; p ≥ 0.10 передаёт заявку сотруднику, p ≥ 0.30 отмечает высокий риск. Отказа только по ML нет. Это синтетическая оценка риска просрочки, а не вероятность одобрения и не проверенная оценка реального заёмщика.

LLM/RAG, реальные ФНС/БКИ и OCR не подключены. Документы проверяются технически и доступны сотруднику; финансовые числа берутся из формы, содержимое файла не распознаётся. Условия не являются условиями Альфа-Банка. Одобрение завершает демонстрацию рассмотрения; подписание и выдача денег не выполняются.

Offline-сравнение на синтетических данных выбрало LogisticRegression C=1; результаты и отдельные команды обучения, оценки и объяснений — в [описании ML-эксперимента](docs/ml-training.md). Качество реального банковского риска не проверено.

## Запуск с нуля

Нужны Docker и Docker Compose с поддержкой `up --wait`. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build -d --wait
docker compose exec backend uv run python -m app.seed
```

[Приложение](http://localhost:8080) · [Swagger UI](http://localhost:8080/api/v1/docs) · [OpenAPI](http://localhost:8080/api/v1/openapi.json)

Обычная сборка использует `INSTALL_ML=false`: JSON с коэффициентами и train-преобразованиями выбранной модели входит в backend-образ. Для инференса не нужны numpy, sklearn, CatBoost, GPU, обучение или локальные папки артефактов разработчика. Отсутствующая или повреждённая обязательная модель даёт технический сбой без кредитного отказа и скрытого перехода к старым правилам. После исправления поставки сотрудник повторяет обработку; закреплённые версии сохраняются.

Backend применяет миграции при запуске. Старые рассмотрения `demo-policy-0.2` сохраняют свою политику и историю, новые отправки используют 0.3. PostgreSQL хранит данные в томе `postgres_data`, загруженные файлы — в `document_data`; обычный `docker compose restart` сохраняет их и серверные сессии. Для повторной демонстрации создавайте новые заявки. Удаление томов уничтожает данные и для обычного обновления не требуется.

В backend работает один встроенный worker; запускайте один процесс Uvicorn. Незавершённый запуск после перезапуска помечается как прерванный, сотрудник повторяет обработку из карточки. Это не внешняя надёжная очередь и не конфигурация для нескольких worker-процессов.

Пароль новых аккаунтов задаёт `DEMO_PASSWORD` в `.env` (в примере `Demo-credit-2026!`). Повторный seed добавляет недостающие записи, сохраняя существующие данные и пароли.

| `client1@example.test` | Клиент, Демо Пекарня |
| `client2@example.test` | Клиент, Демо Мастерская; проверка изоляции |
| `staff@example.test` | Сотрудник |
| `demo-a@example.test` | Клиент, сравнение низкого и повышенного риска |
| `demo-b@example.test` | Клиент, рассмотрение риска и другие условия сотрудника |

[Воспроизводимые сценарии](docs/demo-scenarios.md) содержат значения формы, подготовку файлов и действия обеих ролей. Суммы формы — рубли, суммы API — целые копейки. Финансовые показатели вводятся за весь выбранный период из завершённых календарных месяцев.

## Проверки

На отдельном демонстрационном окружении:

```sh
docker compose run --rm backend uv run pytest -q
docker compose exec backend uv run alembic check
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

В обычном образе проверки offline ML пропускаются, проверки runtime и кредитного процесса выполняются. Набор с offline ML требует extra в отдельном тестовом образе:

```sh
docker compose build --build-arg INSTALL_ML=true backend
docker compose run --rm backend uv run --extra ml pytest -q
# Верните обычный образ перед демонстрацией:
docker compose build --build-arg INSTALL_ML=false backend
```

Проверка parity экспорта дополнительно требует readonly-пути к принятым данным и результатам обучения через `RISK_RUNTIME_DATA` / `RISK_RUNTIME_RUN`; без них этот тест явно пропускается.

Backend-тесты создают и удаляют отдельные временные базы PostgreSQL; пользователь БД должен иметь `CREATEDB` (локальный Compose это позволяет). E2E работают с реальным API и создают данные демонстрационных аккаунтов. Переменные `BASE_URL` и `DEMO_PASSWORD` переопределяют адрес и пароль для E2E; используйте фактический пароль существующих аккаунтов.

Публичный HTTPS и запуск на VPS проверялись 20 октября 2026 года для ревизии `2bde060`; это историческая проверка прежней версии. Сервер обновляется отдельно после публикации проверенной версии в `main`, по [инструкции](docs/deployment.md#обновление-из-main).
