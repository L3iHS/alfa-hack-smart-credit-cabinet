# Умный кредитный кабинет

Проект для хакатона Альфа-Банка 2026: веб-кабинет для подачи и рассмотрения кредитных заявок малого бизнеса.

## Возможности

- Вход клиента и сотрудника с разными правами
- Каталог оборотного кредита и кредита на оборудование
- Данные компании, заполнение и сохранение неполной заявки
- Повторное открытие черновика, редактирование и история изменений
- Защита от перезаписи устаревшей версии заявки
- Загрузка и скачивание PDF, PNG и JPEG до 10 МиБ с проверкой содержимого и прав доступа
- Отправка заполненной заявки с подтверждениями, неизменяемым снимком данных и защитой от повторной отправки
- Статусы «Черновик» и «Отправлена», история и обновление состояния без перезагрузки страницы
- Очередь сотрудника с отправленными заявками и документами; клиентские черновики в неё не попадают

Отправленная заявка ожидает обработки. Проверки ФНС/БКИ, кредитные решения, уточнения, предложения и ML/LLM ещё не реализованы.

## Стек

- Backend: Python, FastAPI, SQLAlchemy, Alembic
- Данные: PostgreSQL
- Frontend: React, TypeScript, Vite
- Запуск: Docker Compose

## Данные и проверки

Для демонстрации используются синтетические компании и финансовые сведения. Условия кредитования демонстрационные. Денежные значения API передаются целым числом копеек; форма отображает рубли.

## Запуск

Нужны Docker и Docker Compose. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build -d
docker compose exec backend uv run python -m app.seed
```

[Приложение](http://localhost:8080) · [Документация API](http://localhost:8080/api/v1/docs) · [OpenAPI](http://localhost:8080/api/v1/openapi.json)

При запуске backend автоматически применяет миграции. PostgreSQL хранит данные в томе `postgres_data`, файлы — в `document_data`. Обычный перезапуск сохраняет данные, файлы и действующие серверные сессии:

```sh
docker compose restart
```

[Инструкция серверного запуска с HTTPS](docs/deployment.md). Публичный HTTPS и запуск на VPS проверены 20 октября 2026 года для ревизии `2bde060`. На стенд переносится конкретная проверенная ревизия из `main`; обновление `dev` само по себе сервер не меняет.

### Демонстрационные учётные записи

Регистрация не требуется. После запуска seed доступны:

| Email | Роль | Компания |
| --- | --- | --- |
| `client1@example.test` | Клиент | Демо Пекарня |
| `client2@example.test` | Клиент | Демо Мастерская |
| `staff@example.test` | Сотрудник | — |

Пароль при первом заполнении — значение `DEMO_PASSWORD` из `.env` (в примере `Demo-credit-2026!`). Повторный запуск seed добавляет недостающие записи и сохраняет существующие данные и пароли.

API использует cookie сессии. Перед изменяющими запросами получите токен через `GET /api/v1/auth/csrf` и передавайте cookie и заголовок `X-CSRF-Token`. Успешный вход возвращает новый токен; прежняя сессия отзывается. Сессия действует 8 часов по умолчанию (`SESSION_TTL_SECONDS`). Для размещения за HTTPS задаётся `COOKIE_SECURE=true`.

### Отправка заявки

Сохраните черновик, заполните цель, сумму, срок и финансовые показатели за завершённые календарные месяцы. Нулевые показатели допустимы; незаполненные поля не заменяются нулями. В карточке прикрепите финансовые сведения, а для оборудования также счёт, подтвердите данные и демонстрационную проверку БКИ.

Отправка меняет состояние на «Отправлена» и закрывает редактирование. Сотрудник видит заявку и её файлы. Пока конвейер рассмотрения не подключён, статус остаётся «Отправлена»; это не означает одобрение.

API загрузки принимает исходное тело файла с Content-Type и параметрами `document_type`, `filename`, `expected_version`. Отправка `POST /api/v1/applications/{id}/submit` требует `Idempotency-Key` в формате UUID. При потере ответа повторяйте тот же ключ и тело: сервер вернёт прежний результат. Подробные схемы доступны в OpenAPI.

### Проверки

```sh
docker compose run --rm backend uv run pytest -q
docker compose exec backend uv run alembic check
```

Backend-тесты используют отдельную временную базу PostgreSQL, применяют миграции и удаляют только эту тестовую базу. Для её создания пользователь PostgreSQL должен иметь право `CREATEDB`; в локальном Compose оно доступно. Данные приложения эти тесты не очищают.

Сборка и браузерные проверки требуют Node.js и запущенного приложения с демонстрационными аккаунтами:

```sh
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты работают с реальным API и создают черновики, документы и отправленные заявки в демонстрационных аккаунтах. Если пароль изменён, передайте то же значение в переменной `DEMO_PASSWORD` при запуске тестов. Адрес приложения переопределяется переменной `BASE_URL`.
